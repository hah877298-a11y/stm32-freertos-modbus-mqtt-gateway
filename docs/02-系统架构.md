# 系统架构

## 1. 任务划分

| 任务 | 栈（字） | 优先级 | 周期 | 职责 |
|---|---|---|---|---|
| `task_led` | 128 | 1 | 500 ms | LED0 心跳 / 远程常亮；按 `alarm` 驱动 LED1 |
| `task_print` | 256 | 2 | 1 s | 打印运行心跳；每 5 s 打印状态与栈水位 |
| `task_key` | 192 | 3 | 20 ms | 扫描 KEY1，打印按键次数 |
| `task_modbus` | 192 | 2 | 约 3 s | DS18B20 转换与读取，Modbus 轮询 3 个寄存器 |
| `task_i2c` | 256 | 1 | 5 s | 扫描 I2C 总线，读 MPU6050，计算振动 |
| `task_esp` | 512 | 1 | 5 s + 事件 | AT 初始化、联网、MQTT 上报、收命令 |
| `task_lcd` | 320 | 1 | 500 ms | 刷新本地界面 |

优先级数字越大越高。所有任务都是死循环 + `vTaskDelay()`，不允许 `return`。

两个栈相关的经验值：

- `task_esp` 用到 `sprintf` 拼 JSON，512 字起步，给小了会 HardFault。
- `task_lcd` 里有浮点 `printf`，256 字会溢出，实测 320 才稳。

## 2. 共享状态

```c
typedef struct {
    uint16_t modbus_temp_x10;      /* 250 = 25.0 ℃ */
    uint16_t modbus_humidity_x10;  /* 500 = 50.0 % */
    uint16_t modbus_status;
    uint8_t  modbus_ok;
    int16_t  local_temp_x10;       /* 256 = 25.6 ℃ */
    uint8_t  ds18b20_ok;
    uint16_t vibration_mg;
    uint8_t  mpu_ok;
    uint8_t  alarm;
} gateway_state_t;
```

- 只允许通过 `gateway_state_set_xxx()` 写入，通过 `gateway_state_snapshot()` 整体读出。
- 内部用一把 `xSemaphoreCreateMutex()` 互斥，临界区只做赋值，不做耗时操作。
- 通信失败时**只清 `ok` 标志，保留上一次有效值**，避免云端数值突然跳成 0.0。

温度取值优先级（`gw_temp_x10()`）：

```text
DS18B20 读到有效值   → 用本地值
否则 Modbus 通信正常 → 用 Modbus 温度
否则有历史有效值     → 沿用上一次
```

## 3. 数据流

```text
task_modbus ──┐
task_i2c    ──┼──▶ gateway_state_t ──snapshot──▶ task_lcd  (显示)
              │          ▲              └───────▶ task_esp (每 5 s 发 MQTT)
              │          │              └───────▶ task_led (报警灯)
              │      互斥锁保护
              └── 远程命令 {"led":1|0} 由 task_esp 解析后写入 g_led_cmd
```

## 4. MQTT 报文

| 方向 | 主题 | 载荷 |
|---|---|---|
| 上行 | `stm32/gw01/telemetry` | `{"t":25.6,"h":50.0,"vib":47,"alarm":0,"mb":1,"up":596}` |
| 下行 | `stm32/gw01/cmd` | `{"led":1}` 常亮 / `{"led":0}` 恢复闪烁 |

- 上行用 QoS1（报文头 0x32），带 2 字节报文号，靠 PUBACK 判活，失败 3 次重连。
- 下行订阅 QoS0，解析时只做一次字符串匹配 `"led":`，够用且不引入 JSON 库。

报文长度字节是手写的：剩余长度只支持单字节编码（小于 128 字节），
所以主题和载荷都不能太长，超了会拼出错误报文。
